# Voice agents configuration contract v1

M0 provides a contract and storage foundation. It does not provide agent CRUD,
publication, telephony destinations or provider calls.

The canonical schema and synthetic example are in
`freepbx/var/www/html/freepbx/rest/lib/agents/contracts/`. Satellite ships an
identical schema in `voice_agent/`; the cross-repository test detects drift.
PHP's `PublishedContract` is usable directly without initializing Slim or FreePBX.

## IDs and admission

| Field | Meaning |
| --- | --- |
| `agent_id` | Stable lowercase identifier, maximum 48 ASCII characters; never a display name |
| `destination_id` | `agent:<agent_id>` for the native agent destination |
| `workflow_version` | Positive immutable publication number, scoped to one agent |
| `provider_binding_id` | Reference to a PHP-owned provider binding; no credential in the snapshot |
| `run_id` | UUID generated by Satellite for one execution |
| `linkedid` | Bounded opaque Asterisk call correlation, maximum 128 ASCII characters; monitoring only |
| `provider_call_id` | Bounded opaque provider correlation, maximum 128 ASCII characters; monitoring only |
| `event_id` | UUID identifying one monitoring event; primary-key deduplication |

A v1 snapshot describes one Basic Voice conversation. It includes the provider
name, conversation text/language/voice, explicitly enabled tools, approved
extension destination IDs, fallback extension ID and maximum call duration.
Unknown fields are rejected, including secrets and model-supplied dialplan targets.
Only `directory.find_destinations` and `telephony.transfer` can be enabled.
No binding secret or trusted ARI target is encoded in this contract.

All configuration integer fields must be JSON integers (no floats or booleans).
The serialized UTF-8 JSON is limited to 64 KiB. IDs cannot contain line breaks;
the destination must match the agent ID. Lists contain unique items. Bounds and
negative fixtures are enforced in PHP and Python. Changing these semantics
requires a new contract version and compatibility tests.

## Storage and ownership

Migration `001-foundation.sql`, invoked by PHP `Schema::install()` from the
existing image update hook, creates new `voice_agent_*` tables. It does not adopt
or modify the former `satellite_agent_*` tables. The caller must already have
created the normal `asterisk` and `asteriskcdrdb` databases.

Configuration tables: agents, editable drafts, immutable versions and audit.
MariaDB triggers deny update/delete of published versions. The enabled agent
pointer chooses its active version. A disabled, unpublished or unresolved agent
is absent from the `voice_agent_published` view. Satellite queries only that view,
checks its row identifiers against the JSON and returns a detached snapshot.

Future publication must validate the entire snapshot, check the expected draft
revision, insert a new immutable version, update the active pointer and append
an audit record in one transaction. These CRUD/publication services are v0.1 work;
the presence of the schema does not mean they are implemented.

Monitoring tables: runs and events. Runs carry the pinned version and correlation
IDs. Event types are bounded by an enum, event IDs deduplicate inserts, and each
run has a required retention deadline. There are no transcript, audio or raw tool
payload columns. Runtime event queues, retention workers and recovery are v0.1 work.

## Least privileges

Provision separate identities with different generated passwords through the NS8
private secrets mechanism, never in Git, environment metadata or the frontend.
No persistent runtime identities are provisioned by M0. The disposable integration
tests create two empty-password accounts accessible only on the disposable test DB
bound to loopback; do not reuse those accounts on an installation.

The configuration reader needs only:

```sql
GRANT SELECT ON asterisk.voice_agent_published TO <configuration_reader>;
```

The monitoring writer needs only:

```sql
GRANT SELECT, INSERT ON asteriskcdrdb.voice_agent_runs TO <monitoring_writer>;
GRANT UPDATE (provider_call_id, ended_at, outcome, error_code)
  ON asteriskcdrdb.voice_agent_runs TO <monitoring_writer>;
GRANT SELECT, INSERT ON asteriskcdrdb.voice_agent_run_events TO <monitoring_writer>;
```

The placeholders are identities provisioned outside this documentation, not literal
SQL account names. Neither identity gets DDL or DELETE. The reader cannot read
drafts, audit or base version tables; the writer cannot read configuration or
change a run's agent/version/retention. Retention administration uses a separate
privileged maintenance identity. PHP configuration and monitoring read identities
remain under the existing FreePBX administrative authorization contract.

## Browser boundary

The compiled Vue app is served at `/freepbx/agents-ui/`, using hash navigation.
Its only M0 backend request is authenticated `GET /freepbx/rest/agents/access`.
The response declares `milestone: M0`, `contract_version: 1`, empty capabilities
and an identity-bound CSRF token. Global Wizard `User`/`Secretkey` authentication
establishes the server-side `nethvoice_admin` attribute. Cross-site browser origins
are rejected; the response is not cached. No mutation endpoints exist in M0.
Future mutations must require the existing header authentication and `X-Agents-CSRF`.

## Implemented v0.1 configuration slice

The M0-only descriptions above record the foundation gate. CRUD, publication,
provider bindings, immutable built-in tool manifests, runtime accounts, pending
correlation, execution and retention are now implemented by migrations 002–005
and their PHP/Python services. See [Basic Voice configuration](voice-agents-v01.md)
for the current API and verified boundaries. Contract version one implies built-in
tool manifest version one; PHP owns those definitions and runtime checks exact
supported versions at call admission. The configuration reader additionally needs
SELECT on `voice_agent_runtime_bindings`, `voice_agent_extension_directory` and
`voice_agent_runtime_tools`. The writer additionally needs SELECT/INSERT and only
UPDATE of state/provider_call_id on `voice_agent_pending_calls`. The server now
reports `v0.1-configuration` with agents/trunks/tools/activity capabilities. Live
provider calls and transfer/media acceptance remain separate gates.
